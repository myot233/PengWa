# 碰碰娃数据协议

Android 与将来的 iOS 版共用这份规格。实现位于 `app/src/main/kotlin/app/pengwa/ble/BleProtocol.kt`，
测试位于 `app/src/test/kotlin/app/pengwa/ble/BleProtocolTest.kt`。

## 身份

| 字段 | 说明 |
|---|---|
| ID | GUID（UUID v4），首次启动时随机生成并永久保存；清除数据或重装后会重新生成 |
| 显示名 | 用户自定义，Unicode NFC 规范化，去首尾空白，UTF-8 编码后 **1–32 字节** |

显示名只允许可显示字符，拒绝：控制字符、格式字符（零宽空格 / 连接符、方向覆盖符等）、
换行、代理项残片、私有区、未分配码位、除普通空格外的所有空白，以及韩文填充符（U+115F、U+1160、U+3164、U+FFA0）
和盲文空白（U+2800）。因此 ZWJ 连接的复合 emoji 不可用。
**接收方必须对收到的名字再执行同一套校验**，不合法则整条丢弃。

## 名片编码（NFC 与蓝牙共用）

```
偏移  长度  内容
0     1     版本号，当前为 0x01
1     16    GUID，大端（与 UUID 文本从左到右的字节顺序一致）
17    1–32  显示名，UTF-8
```

总长 18–49 字节。接收方遇到以下任何情况都应丢弃：版本号不是 0x01、总长不在范围内、
UTF-8 非法、名字不是规范形式、名字未通过校验。

## 蓝牙（BLE）

| 项目 | UUID |
|---|---|
| 服务 | `da9c7844-c076-4b1e-9a5f-b9433bc5bac2` |
| 名片特征（只读） | `f5181d1f-bfb7-44d6-bc07-6e14fa5eb21a` |
| 交换特征（只写） | `9826f54e-83fb-4b2c-8fad-a9714333290e` |

- **广播**：可连接广播，数据里只含服务 UUID。**不放 ID 和名字**，避免被路人被动收集。
- **交换流程**：扫描方发现服务 UUID → 连接 → 协商 MTU（建议 ≥ 64）→ 读「名片特征」得到对方名片
  → 把自己的名片写入对方的「交换特征」→ 断开。一次连接完成双向交换。
- **iOS 注意**：CoreBluetooth 广播只能带服务 UUID 和本地名称，不能带自定义数据，所以本协议不依赖广播负载。

## NFC（ISO-DEP / HCE）

实现：`nfc/ApduProtocol.kt`（协议，纯 Kotlin）、`nfc/PengWaHostApduService.kt`（被碰一方）、
`nfc/NfcTagExchanger.kt`（碰别人一方）。测试：`ApduProtocolTest`，其中有把两端直接对接的整次碰触测试。

- **AID**：`F050454E475741`（`F0` 私有应用前缀 + "PENGWA" 的 ASCII），category `other`。
- **一次碰触、一次往返完成双向交换**：

| 步骤 | 发起方 → 被碰方（命令） | 被碰方 → 发起方（响应） |
|---|---|---|
| 1 SELECT | `00 A4 04 00 07 F0504E47574 1 00`（即 AID） | `90 00` |
| 2 EXCHANGE | `80 E0 00 00 Lc [发起方名片] 00` | `[被碰方名片] 90 00` |

- 名片编码见上文，最长 49 字节，在短 APDU 的 255 字节数据域内。
- **会话约束**：必须先 SELECT 成功才接受 EXCHANGE；设备断开（`onDeactivated`）后需重新 SELECT。
- **互惠约束**：被碰方只在收到合法名片后才返回自己的名片，通用读卡器无法白拿；
  这不是安全措施（协议公开），只是避免随手抄走。
- **状态字**：`6A82` AID 不匹配 / `6985` 未 SELECT 或本机还没设置名字 / `6A80` 名片不合法 /
  `6700` 长度错误 / `6D00` 不支持的指令 / `6E00` 不支持的 CLA。
- **读卡方式**：两台手机都用前台调度（Foreground Dispatch）收 IsoDep，保持默认的"既读又被读"，
  **不用 Reader Mode**——它会关掉本机卡模拟，两台都开会谁也读不到谁。
- 屏幕需亮着；`requireDeviceUnlock=false`，不必解锁。

## NFC 标签模拟（标准 AID，让对方系统直接拉起 App）

实现：`nfc/NdefMessages.kt`、`nfc/T4tEmulator.kt`（含 `CardRouter`、`TagShareGate`）、
`nfc/NdefLaunchParser.kt`。测试：`T4tEmulatorTest`（有一个按 NFC Forum 规范读标签的"标准读卡器"）。

同一个 HCE 服务同时响应两个 AID，由 `CardRouter` 按最近一次成功的 SELECT 决定后续命令交给谁：

| AID | 用途 | 对方需要装 App 吗 |
|---|---|---|
| `F050454E475741`（私有） | 两边都装了 App，一次碰触双向交换（上一节） | 需要 |
| `D2760000850101`（NFC Forum NDEF 标签应用） | 被任何手机当作一张标签读取；系统据此直接拉起 App | 读的一方不需要装 App 也能读到数据，但只有装了才会被拉起 |

- **标签内容**：一条 NDEF 短记录，TNF=媒体类型，类型 `application/vnd.pengwa.card`，负载为上文的名片编码。
  整个 NDEF 文件 = 2 字节长度（大端）+ 消息，最长 81 字节。
- **能力文件**（E103，15 字节）：映射版本 2.0、MLe 59、MLc 52、NDEF 文件 E104 最大 255 字节、读不限制、写禁止。
  读卡器按规范依次：SELECT 应用 → SELECT E103 → READ BINARY → SELECT E104 → READ BINARY（分多次，每次最多 59 字节）。
- **App 被拉起**：`MainActivity` 声明了 `NDEF_DISCOVERED` + 上述 MIME 的过滤器，系统直接拉起 App，**不经过网站**。
  意图内容来自外部，解析时重新校验（版本号、UTF-8、显示名规则），不合法的丢弃。
  拉起后会趁手机还贴着，在同一张"卡"上再尝试走私有协议，把自己的名片也交给对方（对方装了 App 才会成功，失败无妨）。
- **"展示名片"开关（`TagShareGate`）**：只有名片页在前台时，SELECT 标准 AID 才会成功；否则返回 `6A82`，
  读卡方看到的就是"这不是一张 NDEF 标签"。离开页面、退到后台、进程被杀都会关闭。私有 AID 不受此开关影响
  （它要求对方先出示合法名片）。
- **AID 争用**：标准 AID 不是我们独占的，系统自带的"嵌入式标签"服务等可能也登记它。App 在前台时通过
  `CardEmulation.setPreferredService` 声明首选，离开前台自动撤销；已在真机上用 `dumpsys nfc` 确认设置和撤销都生效。
- **没装 App 的人**：什么都不会发生（这是 A 阶段的取舍）。要让他们看到下载页，需要把第一条记录改成
  `https` 网址并配置 App Links，见后续的 C 阶段。名片编码保持不变，只是外面的包装从自定义 MIME 换成网址。

## 待定

- **两台手机的真实碰触尚未在真机上验证**（需要两台设备）：默认模式下谁来当读卡方、一次碰触是否稳定只触发一次。
- 蓝牙：两台手机同时扫描 + 广播时会互相连接两次；计划用广播里的短哈希决定谁来发起连接。
- 防冒充：目前 ID 是明文，可被复制；需要时再加签名或挑战应答。
